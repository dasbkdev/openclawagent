# Starlab Agent - план full day assistant

Дата: 2026-06-05

Цель: превратить текущего Telegram/серверного агента в ежедневного рабочего
ассистента для Николая, Максата и ПМ. Агент должен помогать сотруднику
планировать день, выполнять задачи, видеть отставания, получать подсказки,
фиксировать blockers, считать эффективность и отправлять руководителям честные
отчеты по иерархии.

Важно: агент должен быть прозрачным рабочим инструментом, а не скрытой системой
наказаний. Все выводы должны быть основаны на данных и помечаться как
"точно", "примерно" или "нет данных".

---

## 1. Что должен делать агент

### Для ПМ

- Утром собрать список задач на день из Bitrix/Jira/Google Calendar.
- Спросить сотрудника: что сегодня планируешь закрыть?
- Сформировать дневной план:
  - обязательные задачи;
  - дедлайны;
  - встречи;
  - риски;
  - примерную загрузку.
- В течение дня напоминать:
  - что сейчас в приоритете;
  - что просрочено;
  - что не двигалось слишком долго;
  - что надо подготовить к встрече;
  - где есть blocker.
- Помогать ответами в Telegram:
  - "что мне делать сейчас?";
  - "какие задачи горят?";
  - "покажи мой прогресс";
  - "что я должен закрыть до конца дня?";
- Вечером собрать короткий самоотчет:
  - что сделал;
  - что не сделал;
  - почему;
  - что перенести на завтра.
- Показать личную эффективность:
  - выполнено / запланировано;
  - просрочено;
  - активное время по Metricon;
  - фокусное время;
  - количество переключений, если Metricon это отдаст;
  - blockers.

### Для Максата

- Видеть дневной статус по каждому подчиненному ПМ.
- Получать предупреждения:
  - ПМ долго не активен;
  - задачи стоят без движения;
  - дедлайн сегодня, прогресса нет;
  - сотрудник сам отметил blocker;
  - эффективность резко ниже обычной.
- Спрашивать бота:
  - "как сегодня Бегайым?";
  - "кто отстает?";
  - "какие blockers у ПМ?";
  - "что мне доложить Николаю?";
- Получать вечерний сводный отчет по своим ПМ.

### Для Николая

- Видеть всю компанию по иерархии.
- Получать ежедневный отчет:
  - что сделал Максат;
  - что сделали ПМ;
  - какие проекты в риске;
  - какие задачи просрочены;
  - где нужны решения руководителя;
  - сколько токенов потрачено.
- Получать недельный отчет:
  - динамика эффективности;
  - самые проблемные проекты;
  - сотрудники с постоянными blockers;
  - где много активности, но мало закрытых задач.
- Спрашивать бота:
  - "кто сегодня отстает?";
  - "что сделал Максат за день?";
  - "почему project-alpha в риске?";
  - "дай краткий отчет по всем".

## 2. Источники данных

### Bitrix

Основной источник задач и канбана.

Нужно читать:

- проекты/workgroups;
- задачи;
- стадии/статусы;
- ответственных;
- дедлайны;
- постановщиков;
- наблюдателей;
- комментарии, если разрешено;
- историю изменения статуса, если API позволяет.

Важно: Bitrix должен оставаться read-only. Любые write/update/delete методы
запрещены guard'ом в коде.

### Jira

На следующем этапе:

- issues;
- assignee;
- status;
- sprint/board;
- due date;
- comments;
- transitions history.

### Metricon

Источник фактической активности.

Нужно читать:

- рабочие интервалы;
- активное время;
- idle/lock;
- топ приложений/сайтов;
- возможно screenshots/activity categories, если API отдаст.

Важно: сейчас на сервере нет Metricon refresh token, поэтому access token
протухает и данные не читаются стабильно. Для full assistant refresh token
обязателен.

### Google Calendar

Источник встреч и занятости.

Нужно читать:

- встречи на сегодня;
- длительность;
- участники;
- пересечения с дедлайнами;
- свободные окна для фокусной работы.

### Gmail

Только рабочие сигналы:

- письма за день;
- письма от клиента/руководителя;
- непрочитанные важные письма;
- темы, связанные с задачами.

Не использовать Gmail для личных выводов. Только рабочий контекст.

### Google Drive / Docs / Sheets

Источник результата работы:

- какие документы менялись;
- когда менялись;
- какие таблицы обновлялись;
- короткие snippets для контекста Claude.

## 4. Дневной цикл агента

### 08:30-09:30 - Утренний план

1. Сервер собирает задачи из Bitrix/Jira.
2. Сервер собирает встречи из Google Calendar.
3. Агент пишет сотруднику:

```text
Доброе утро. На сегодня вижу 7 задач и 2 встречи.
Главные дедлайны:
1. ...
2. ...

Что реально планируешь закрыть сегодня?
```

4. Сотрудник отвечает текстом.
5. Claude превращает ответ в `dailyWorkPlan`.
6. Агент подтверждает:

```text
Ок, план на день:
- закрыть ...
- проверить ...
- подготовить ...

Я напомню, если появится риск по дедлайну.
```

### 11:30-12:00 - Первый контроль

Агент проверяет:

- есть ли активность по Metricon;
- изменились ли задачи;
- есть ли просрочки;
- есть ли встречи.

Если все нормально, не спамит. Если риск:

```text
Вижу риск: задача X с дедлайном сегодня, но статус еще "в работе".
Нужна помощь или перенос?
```

### 15:00-16:00 - Второй контроль

Агент сравнивает план и факт:

- сколько задач закрыто;
- что осталось;
- сколько активного времени;
- какие blockers.

Сообщение сотруднику:

```text
На сейчас: 2 из 5 задач закрыты.
До конца дня лучше сфокусироваться на:
1. ...
2. ...
```

### 18:00-19:00 - Вечерний отчет

Сотрудник получает:

```text
Итог дня:
- закрыто: 4/6
- в работе: 2
- просрочено: 1
- активное время: 5ч 20м

Что не успел и почему?
```

Потом агент формирует отчет для руководителя.

## 5. Расчет эффективности

Нельзя считать эффективность только по Metricon. Человек может быть активным,
но не закрывать задачи. И наоборот, закрыть важную задачу за 2 часа.

Предлагаемая формула MVP:

```text
overallEfficiency =
  taskCompletionScore * 0.55 +
  deadlineScore * 0.20 +
  focusScore * 0.15 +
  communicationScore * 0.10
```

### `taskCompletionScore`

```text
completed planned tasks / planned tasks
```

### `deadlineScore`

Штраф за просрочки и задачи без движения.

### `focusScore`

По Metricon:

- активное время;
- idle;
- длинные фокусные блоки;
- частые переключения.

### `communicationScore`

По check-ins:

- сотрудник ответил утром;
- отметил blocker;
- дал вечерний отчет;
- не игнорировал критичные напоминания.

Важно: score всегда должен иметь `confidence`.

Пример:

```text
Эффективность: 72%, confidence: средний.
Причина: Bitrix и Google доступны, но Metricon данных мало.
```

## 6. Telegram интерфейс

Основной режим - обычный текст.

Примеры:

```text
Что мне делать сейчас?
Какие задачи горят?
Покажи мой прогресс.
Почему я отстаю?
Сформируй отчет Максату.
```

Команды, которые стоит добавить позже:

```text
/today - мой план и прогресс на сегодня
/plan - создать/изменить план дня
/progress - текущая эффективность
/blocker - отметить проблему
/done - отметить, что задача готова к проверке
/team - сводка команды для руководителя
/daily_report - отчет за день
```

Не надо сразу добавлять много slash-команд в меню. Лучше начать с 3-4 самых
нужных, остальное обрабатывать свободным текстом.

## 7. AI логика

Claude должен быть не просто чатиком, а "рабочим диспетчером".

Нужны отдельные промпты/режимы:

### `daily_planner`

Собирает план дня из задач, календаря и ответа сотрудника.

### `progress_coach`

Помогает сотруднику понять, что делать дальше.

### `risk_detector`

Ищет просрочки, blockers, отсутствие движения.

### `manager_reporter`

Пишет краткий отчет руководителю без лишней болтовни.

### `executive_summary`

Пишет отчет Николаю: только факты, риски, решения.

## 8. Иерархия доступа

Сохранить текущие правила:

- Николай видит всех.
- Максат видит себя и своих ПМ.
- ПМ видит только себя и свои проекты.

Отчеты вверх:

```text
ПМ -> Максат -> Николай
ПМ -> Николай, если Николай запрашивает напрямую
Максат -> Николай
```

ПМ не должен видеть чужую эффективность и отчеты.

## 10. Реализация по этапам

### Этап 0 - закрыть интеграционные дыры

Обязательно до full assistant:

- сохранить Metricon refresh token;
- заменить Bitrix webhook на read-capable webhook;
- выдать Bitrix scopes: `task`, `sonet`, `user_brief`, возможно `crm`;
- определить реальные Bitrix group/project IDs;
- проверить, где именно живет канбан: Tasks или CRM.

### Этап 1 - Daily plan MVP

- добавить `dailyWorkPlans`;
- добавить утренний check-in;
- добавить `/today`;
- сохранять план сотрудника;
- показывать план и текущие задачи.

### Этап 2 - Progress tracking

- каждые 1-2 часа собирать snapshot:
  - Bitrix tasks;
  - Metricon activity;
  - Calendar;
  - Google Drive changes.
- считать `workMetricsDaily`;
- добавить `/progress`;
- отправлять мягкие nudges только при риске.

### Этап 3 - Evening reports

- вечерний check-in сотруднику;
- отчет Максату по ПМ;
- отчет Николаю по всем;
- хранить `managerReports`.

### Этап 4 - Risk detector

- правила риска:
  - deadline today + no progress;
  - overdue;
  - low activity + many planned tasks;
  - no morning plan;
  - repeated blockers;
  - task stuck in same stage.
- severity:
  - info;
  - warning;
  - critical.

### Этап 5 - Dashboard

- web dashboard для Николая/Максата;
- таблица сотрудников;
- задачи;
- эффективность;
- риски;
- история отчетов.

### Этап 6 - Postgres

JSON state подходит для MVP, но для ежедневного ассистента лучше Postgres:

- стабильнее;
- проще аналитика;
- можно хранить историю;
- меньше риска потерять данные при параллельных записях.

## 11. Что нельзя делать

- Нельзя давать Claude секреты.
- Нельзя позволять Bitrix write/delete/update без отдельного ручного approval.
- Нельзя делать вывод "сотрудник плохо работает" без confidence и причин.
- Нельзя спамить сотрудников каждые 10 минут.
- Нельзя считать только активность мышки/клавиатуры эффективностью.
- Нельзя показывать ПМ данные других ПМ.

## 12. Первый практический спринт

Самый правильный следующий спринт:

1. Починить реальные данные:
   - Metricon refresh token;
   - Bitrix webhook scopes/access;
   - реальные Bitrix project mappings.
2. Добавить `dailyWorkPlans`.
3. Добавить `/today`.
4. Добавить утренний check-in.
5. Добавить вечерний check-in.
6. Добавить дневной отчет Николаю.

После этого продукт уже будет ощущаться как настоящий рабочий ассистент, а не
просто бот с отчетами.
