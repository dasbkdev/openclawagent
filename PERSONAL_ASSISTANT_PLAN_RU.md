# Личные ассистенты руководителей (Николай, Анастасия) — заготовка

Цель: на личные Маки Николая и Анастасии поставить OpenClaw как **полностью
личного ассистента** (психология, здоровье, привычки, жизнь), память хранится
**на нашем сервере**, но в **полностью отдельной области**, не пересекающейся с
рабочим контуром. Изоляция — **уровень B (отдельный процесс)**. Память видит
**только сам пользователь**. Шифрования нет (по решению владельца). Имя ассистента
выбирает сам пользователь.

Статус: **серверный фундамент готов и протестирован** (этот документ — что уже
есть и что осталось включить/поставить).

---

## Что уже сделано (код, без Mac) — `control-plane/src/personal/`

Полностью отдельный личный контур, ничего общего с рабочим:
- **`personal-store.js`** — хранилище личной памяти: ОТДЕЛЬНАЯ Postgres-таблица
  `personal_assistant_state`, **одна строка на пользователя** (физическая изоляция
  + строго single-user). Не трогает `control_plane_state`.
- **`personal-identity.js`** — отдельные коды активации и токены
  (`personal_codes`, `personal_identity`), не связаны с рабочими device-agents.
  Токен → ровно один пользователь.
- **`personal-assistant.js`** — `answerPersonalAssistant`: персона под психологию/
  здоровье/жизнь, тёплый тон, дисклеймеры (не врач/не психотерапевт), личная
  память (факты + диалог), семантический recall через Voyage. **Никаких** Platrum/
  Metricon/Google-работы/иерархии. Личный дистиллятор фактов (health/mood/habit/
  goal/relationship).
- **`personal-router.js`** + **`personal-server.js`** — ОТДЕЛЬНЫЙ процесс (порт
  `PERSONAL_PORT`=3100), эндпоинты:
  - `POST /v1/chat/completions` — OpenAI-совместимый, авторизация Bearer личным
    токеном → строго этот пользователь.
  - `GET  /v1/models` → `starlab-personal`.
  - `POST /api/v1/personal/activate` — `{code}` → `{token,userId}`.
  - `POST /api/v1/personal/issue-code` — админ (X-Actor-Telegram-Id) выдаёт код.
  - `POST /api/v1/personal/profile` — пользователь задаёт ИМЯ своего ассистента.
- Тесты: `test/personal-assistant.test.js` (изоляция стора, идентичность,
  персона без рабочих данных, дистилляция). Запуск: `npm run personal`.

Изоляция от рабочего контура: отдельный процесс, отдельные таблицы, отдельная
модель `starlab-personal`, отдельный порт, отдельные токены. Личные данные не
попадают в рабочие отчёты, `/tokens`, аудит или бэкапы рабочего state.

## Что осталось включить на сервере (когда скажешь — сделаю)

1. **systemd-сервис** `company-personal-assistant.service` (запускает
   `npm run personal`, env из `/etc/company-control-plane/control-plane.env`,
   `PERSONAL_PORT=3100`). Схемы таблиц создаются автоматически при старте.
2. **nginx**: отдельный публичный путь/субдомен на `127.0.0.1:3100`. Рекомендую
   **субдомен** `personal.starlabagent.pp.ua` (чище, чем путь) ИЛИ
   `location ^~ /personal/v1/`. С TLS.
3. **Отдельные бэкапы** личных таблиц (`personal_*`) — добавить в backup-runtime.sh
   (или отдельный таймер), не смешивая с рабочим дампом.
4. **Выдать коды**: `POST /api/v1/personal/issue-code` для Николая и Анастасии
   (их userId в state) → получить персональные коды активации.

## Установка на Маки (когда включишь SSH)

OpenClaw официальный, без ребренда обязательного (можно и ребренд). Главное —
нацелить провайдер на личный эндпоинт:
1. Поставить официальный OpenClaw на Mac Николая и на Mac Анастасии.
2. Активация: ввести персональный код → `POST /api/v1/personal/activate` →
   получить личный токен.
3. В настройках OpenClaw провайдер = openai-compatible:
   - `baseURL = https://personal.starlabagent.pp.ua/v1` (или согласованный путь),
   - `apiKey = <личный токен>`,
   - модель `starlab-personal`.
4. Пользователь сам задаёт имя ассистента (`/api/v1/personal/profile`).
5. Проверка: спросить что-то личное, на след. день проверить, что помнит; убедиться,
   что у Николая и Анастасии память РАЗНАЯ и ничего не «течёт» в рабочий контур.

SSH к Макам: пользователь включит Remote Login и добавит мой ключ (как делали с
Mac Максата). Anastasia в другом офисе → через интернет/Tailscale.

## Приватность (зафиксировано)
- Память строго single-user: токен → один пользователь; чужую память прочитать
  нельзя (нет эндпоинта и нет иерархии).
- Личный контур не вызывает рабочие интеграции и не пишет в рабочую память.
- Шифрование не делаем (решение владельца). При желании позже можно добавить.

## Открытые технические вопросы (решим при установке)
- Нужен ли OpenClaw **SSE-стриминг** на `/v1/chat/completions` — если конкретный
  экран требует, добавлю потоковый ответ.
- Субдомен vs путь для nginx (рекомендую субдомен + отдельный TLS-сертификат).
